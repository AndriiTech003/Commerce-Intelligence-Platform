# 01 · Продукт и границы (scope)

## Роли

| Роль | Где работает | Что может |
|---|---|---|
| **Platform admin** | admin (`/platform`) | Видит список тенантов, блокирует, смотрит здоровье системы. Минимум UI |
| **Owner** мерчанта | admin | Всё в своём тенанте, включая сотрудников и API-ключи |
| **Admin** мерчанта | admin | Всё, кроме управления владельцем и биллингом |
| **Catalog manager** | admin | Товары, категории, склад, скидки |
| **Marketer** | admin | Кампании, креативы, сегменты, эксперименты, аналитика |
| **Support** | admin | Заказы (просмотр, смена статуса, возврат), покупатели (read-only) |
| **Customer** | storefront | Каталог, корзина, checkout, личный кабинет, история заказов |
| **Anonymous visitor** | storefront | Каталог, корзина (по `anonymous_id`), трекинг событий |

Права — RBAC с **permissions**, а не проверкой ролей в коде:
`catalog:read`, `catalog:write`, `inventory:write`, `orders:read`, `orders:manage`, `customers:read`, `marketing:write`, `marketing:approve`, `analytics:read`, `staff:manage`, `apikeys:manage`, `settings:write`. Роль = набор permissions (хранится в коде как константа + проверяется guard'ом).

## Модули и фичи

### A. Tenancy & Identity
- Регистрация мерчанта → создаётся тенант (`slug`), пользователь-owner, дефолтные настройки, demo-данные (опционально чекбокс «заполнить демо-каталогом»).
- Приглашение сотрудников по email (токен с TTL 72h, ссылка в Mailpit в dev).
- Один пользователь может состоять в нескольких тенантах → переключатель тенанта в админке.
- Auth: access JWT (15 мин) + refresh token (httpOnly cookie, rotation, reuse detection → отзыв всей семьи токенов).
- Покупатели — отдельная сущность `customers` в рамках тенанта (email уникален внутри тенанта).
- API-ключи мерчанта: `pk_live_…` (публичный, только запись событий, для tracker-sdk) и `sk_live_…` (серверный, scopes). Хранится только hash + prefix.
- Audit log всех изменений в админке (кто, что, diff).

### B. Catalog
- Категории (дерево, до 3 уровней).
- Товар: title, slug, description (markdown), brand, status (`draft|active|archived`), изображения (S3-совместимое хранилище: MinIO в dev), атрибуты (JSONB), теги.
- Варианты (SKU): цена, compare-at цена, атрибуты варианта (size/color).
- Поиск в админке и на витрине: PostgreSQL full-text (`tsvector`) + trigram для опечаток. (Не Elasticsearch — ADR.)
- Embedding товара (для рекомендаций) пересчитывается асинхронно при изменении title/description/attributes.
- Bulk import CSV (фоновая задача с прогрессом) — хорошая демонстрация job-processing.

### C. Inventory
- `on_hand`, `reserved`, `available = on_hand - reserved`.
- Резерв при начале checkout на 15 минут; истечение — фоновой задачей.
- Ручная корректировка с причиной (попадает в `inventory_movements`).
- Low-stock порог → событие `inventory.low_stock` → уведомление в админке.

### D. Cart & Checkout
- Корзина для анонимного пользователя (по `anonymous_id` из cookie) и для залогиненного; **merge при логине**.
- Цены в корзине пересчитываются при каждом чтении; изменение цены показывается пользователю.
- Скидки: промокод (percent / fixed), min subtotal, даты действия, лимит использований (глобальный и на покупателя).
- Checkout: адрес → доставка (фиксированные тарифы) → оплата.
- Оплата через интерфейс `PaymentProvider`:
  - `FakePaymentProvider` (по умолчанию для демо: карта `4242…` успех, `4000…0002` отказ, асинхронный вебхук через 2 сек);
  - `StripeProvider` (test mode, опционально).
- Вебхук оплаты: проверка подписи, идемпотентная обработка (`provider_event_id` уникален).
- `Idempotency-Key` обязателен для `POST /checkout`.

### E. Orders
- Статусная машина: `pending_payment → paid → fulfilled → delivered`, ветки `cancelled`, `refunded`, `payment_failed`. Недопустимые переходы — ошибка домена.
- История статусов, заметки сотрудников.
- Возврат (полный) → событие `order.refunded` → возврат на склад.
- Email-уведомления покупателю (через Mailpit в dev) — из `domain-worker`.

### F. Customers
- Список, карточка покупателя: заказы, LTV, последние события (из ClickHouse), **профиль персонализации** (интересы, сегменты) — очень эффектно на демо.

### G. Analytics (realtime + исторические)
- **Live**: активные посетители (последние 5 мин), events/sec, выручка сегодня, заказы сегодня, лента последних событий.
- **Исторические**: выручка по дням, заказы, AOV, конверсия, воронка `product_viewed → add_to_cart → checkout_started → order_placed`, топ товаров, топ категорий, retention по когортам (недельные).
- Фильтры по периоду, сравнение с прошлым периодом.
- **AI Insights** (M7, опционально): LLM получает **только агрегаты** из ClickHouse (не сырые данные) и формулирует 3–5 наблюдений. Каждое наблюдение ссылается на конкретный запрос/цифры — никаких галлюцинаций без данных.

### H. Personalization & Campaigns (подробно в `06-personalization-engine.md`)
- Профиль покупателя в реальном времени.
- Сегменты (правила над признаками профиля).
- Рекомендации на витрине: «Для вас», «Похожие товары», «С этим покупают».
- Кампании: место показа (placement) + товары + сегменты + креативы.
- Генерация креативов LLM → ревью → approve.
- Автоматический выбор креатива (Thompson sampling) для каждого сегмента.
- Экран эксперимента: распределение трафика по вариантам во времени, CTR/CVR с доверительными интервалами.
- «Why this ad?» — объяснение для конкретного показа.

### I. Simulator (для демо)
- Персоны со скрытыми предпочтениями, генерация сессий, управление из админки (старт/стоп, интенсивность).

## Что **не** входит в проект (осознанно)

Записать в README в раздел *Non-goals* — это сигнал зрелости:

- Налоги, мультивалютность, международная доставка
- Реальные платежи и PCI DSS
- Мультиязычность контента
- Маркетплейс (несколько продавцов в одном заказе)
- Кастомные темы витрины / page builder
- Email-маркетинг, SMS
- Полноценный ML (обучение моделей). Используем эвристики + bandits + embeddings — объяснимо и достаточно
- Kubernetes (docker compose + опциональный Terraform)

## Demo-тенанты (seed)

| Тенант | Каталог | Зачем |
|---|---|---|
| `runhub` | Спорт/бег: ~300 товаров | Главный демо-магазин, персоны «бегун», «турист», «новичок» |

Каталог генерируется скриптом (фиксированный seed, чтобы данные были стабильными), картинки — из открытых источников с лицензией или плейсхолдеры.
